# Формат файлов Paradox (BDE) — вскрытые детали

Всё ниже проверено побайтовым сравнением с файлами, созданными настоящим BDE
(Database Desktop / учётная система на BDE), на реальной базе из ~130 таблиц.
Смещения — от начала файла. Числа little-endian, если не сказано иное.

## 1. Общий заголовок (все файлы: .DB, .PX, .X*, .Y*)

| Смещение | Размер | Поле | Примечание |
|---------:|-------:|------|-----------|
| 0x00 | 2 | recordSize | размер записи в байтах |
| 0x02 | 2 | headerSize | обычно 0x0800 = 2048 |
| 0x04 | 1 | fileType | см. таблицу типов ниже |
| 0x05 | 1 | maxTableSize | **blocksize в KB** (1..32); данные идут блоками этого размера |
| 0x06 | 4 | numRecords | всего записей в файле |
| 0x0A | 2 | usedBlocks | занятых блоков |
| 0x0C | 2 | fileBlocks | блоков всего |
| 0x0E | 2 | firstBlock | первый блок цепочки (1-based) |
| 0x10 | 2 | lastBlock | последний блок цепочки |
| 0x12 | 2 | version-байты | у BDE-файлов своё значение на файл; pxlib пишет своё → **не трогать / графтить** |
| 0x15..0x1C | | служебные счётчики/время | BDE обновляет; можно игнорировать |
| 0x20 | 1 | **число уровней индекса** | для PX-формата: 1, 2, 3… |
| 0x21 | 2 | numFields | |
| 0x23 | 2 | primaryKeyFields | у X-файлов = numFields−1 (ключ сортировки) |
| 0x29 | 1 | sortOrder | 0x00 ASCII, 0xC0 'intl'/national |
| 0x2C..0x2F | 4 | version/change-байты | графтить из BDE-файла |
| 0x30..0x37 | 8 | указатели (runtime) | мусор из памяти пишущего процесса; BDE игнорирует |
| 0x3A | 2 | maxBlocks | = fileBlocks |
| 0x49..0x4C | 4 | autoInc / ID | графтить |
| 0x58+ | | указатели и **имя таблицы** (ASCIIZ) | BDE пишет короткое имя (напр. `resttemp.DB`); pxlib — полный путь (**ломает BDE**) |
| 0x64..0x77 | | hiFieldID + **DOS-кодовая страница (0x6A, 2 байта)** + unknown | у кириллических баз 0x6A = 866; pxlib пишет 1252 (**ломает BDE**). В .PX/.Y* это смещение занято текстом имени — не трогать |
| дальше | | описатели полей, имена полей (ASCIIZ), **имя языкового драйвера** | напр. `cyrr` (кириллица); pxlib пишет `ANSIINTL` (**ломает BDE**) |

### Значения fileType

| Значение | Файл |
|---------:|------|
| 0 | .DB с primary index (IndexDB) |
| 1 | .PX (primary index) |
| 2 | .DB без индекса |
| 4 | .Ynn |
| 5 | .Xnn |
| 7 | .YGn |
| 8 | .XGn |

## 2. Блоки данных

Файл = заголовок (headerSize) + блоки по `maxTableSize` KB. Каждый блок:

```
+0x00  2  nextBlock   (номер следующего блока цепочки; 0 = последний)
+0x02  2  prevBlock   (0 = первый)
+0x04  2  addDataSize (= (n_записей - 1) * recordSize)
+0x06     записи подряд, без зазоров
```

Цепочка блоков (`firstBlock` → `nextBlock` → …) идёт **в порядке первичного
ключа** — Paradox кластеризует данные по PK. Внутри блока записи также
отсортированы. Пустой блок: addDataSize=0 и нулевые байты записи.

### Кодирование полей в записи

Ключевые поля кодируются так, что **memcmp сырых байт = логический порядок**:
целые/даты — big-endian со знаковым флипом старшего бита (значение + 0x8000…),
Alpha — байты кодировки (cp866 и т.п.) с дополнением нулями.
«Blank» (пусто) для Number — все нули; `0.0` — `80 00 00 00 00 00 00 00`.
Это **разные** значения: пересериализация blank→0.0 портит данные.

## 3. Вторичные индексы: .Xnn / .XGn

X-файл — обычная Paradox-таблица со схемой:

```
[поля индекса…, PK-поля родителя, 'Blk Num' (Short)]
```

* `primaryKeyFields` = все поля кроме `Blk Num` (ключ сортировки);
* записи отсортированы по ключу; дубликаты — в порядке (блок, позиция);
* `Blk Num` = **физический номер data-блока** записи в родительском .DB
  (1-based);
* кодовая страница X-файла (0x6A) должна совпадать с родительским .DB.

`.Xnn` — индекс по одному полю nn; `.XGn` — составной (G = групповой).

## 4. PX-формат: .PX, .Ynn, .YGn — это B-дерево

`.PX` — индекс над `.DB`; `.Ynn`/`.YGn` — **точно такой же индекс над
X-файлом**. recordSize = длина ключа + 6.

Запись индекса:

```
key (recordSize-6 байт) + short(blockNr) + short(count) + short(0)
```

`short` = 2 байта big-endian + 0x8000 (знаковый флип).

### Структура уровней

* **Листовой уровень**: запись на каждый непустой data-блок базового файла —
  (минимальный ключ блока, номер блока, число записей в блоке).
* Если листья не влезают в один блок — строится **корень** (блок 1): запись
  на каждый листовой блок — (первый ключ листа, номер блока-листа,
  сумма покрытых записей). При необходимости появляются mid-уровни (3+).
* Порядок блоков в файле: корень (блок 1) → уровни сверху вниз до листьев;
  цепочка next/prev проходит блоки в этом порядке.
* **Заполнение** блока уровня: ёмкость − 1 (например 203 при ёмкости 204).
* **covered ≤ 32767**: сумма покрытых записей в одной записи узла не может
  превышать short — при переполнении лист режется раньше.
* Байт `0x20` заголовка = число уровней; `numRecords` = записи всех уровней.

pxlib `PX_write_primary_index` пишет вместо этого плоский список в порядке
физических блоков — BDE такой «индекс» не принимает (и порядок ключей
нарушается, если цепочка блоков не совпадает с физическим порядком).

## 5. Типичные ошибки BDE и их причины

| Ошибка BDE/приложения | Причина |
|---|---|
| Table is corrupt / не открывается | unix-путь вместо имени в заголовке; version-байты pxlib |
| Language mismatch / кракозябры | языковой драйвер `ANSIINTL`, кодовая страница 1252 вместо 866 |
| Index is out of date | вторичные индексы не пересобраны; Blk Num устарели |
| Index sort order mismatch | sortOrder .PX ≠ sortOrder таблицы (pxlib пишет 0x62 'b') |
| Нули вместо пустых значений | blank→0.0 при пересериализации Number |
| Segfault процесса при вставке | Alpha-значение длиннее поля (переполнение буфера pxlib) |
