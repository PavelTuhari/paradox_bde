# pxbde — безопасное редактирование таблиц Paradox (BDE)

Библиотека Python поверх [pxlib](http://pxlib.sourceforge.net/)/[pypxlib](https://pypi.org/project/pypxlib/),
которая умеет **записывать** в таблицы Paradox так, что их продолжают открывать
BDE-приложения (Database Desktop, учётные системы на Delphi/BDE и т.п.).

Голый pxlib читает Paradox отлично, но при **записи** делает файлы, которые BDE
считает повреждёнными («Table is corrupt», «Index is out of date», language
mismatch). pxbde закрывает все известные проблемы — каждая найдена побайтовым
сравнением с эталонными файлами, созданными самим BDE.

## Поддерживаемые файлы таблицы (все расширения)

| Файл | Что это | Поддержка pxbde |
|------|---------|-----------------|
| `.DB` | данные | чтение, вставка, RAW-pack (без пересериализации байт записей) |
| `.PX` | primary index | полная пересборка в родном формате B-дерева (1..N уровней) |
| `.MB` | blob-данные | чтение через pxlib; **запись**: `mb_append_blobs` + `make_blob_info` (suballocated-блоки type 3, формат вскрыт побайтово) |
| `.VAL` | validity/referential | сохраняется как есть |
| `.Xnn` (fileType 5) | вторичный индекс (одиночный) | полная пересборка |
| `.XGn` (fileType 8) | вторичный индекс (составной) | полная пересборка |
| `.Ynn` (fileType 4) | «PX над X» для `.Xnn` | полная пересборка |
| `.YGn` (fileType 7) | «PX над X» для `.XGn` | полная пересборка |

Database Desktop для пересборки индексов **не требуется**.

## Что именно ломает pxlib (и чинит pxbde)

1. **Имя таблицы в заголовке** — pxlib пишет полный unix-путь
   (`/var/folders/.../table.DB`) вместо короткого имени; BDE отвергает файл.
2. **Version-байты** (`0x12`, `0x2C`) — заменяются на pxlib-овские.
3. **Языковой драйвер** — pxlib пишет `ANSIINTL`; кириллическим базам нужен
   родной (например `cyrr`) → BDE: *language mismatch*.
4. **DOS-кодовая страница** (`0x6A`) — pxlib ставит 1252 вместо 866.
5. **blank ≠ 0.0** — пересериализация Number превращает «пустые» значения в
   нули (обнаружено сотнями тысяч на реальной базе).
6. **Multi-insert с привязанным `.PX`** падает (free-slot / block header bug).
7. **`PX_create_file`** по умолчанию ставит maxtablesize=3, теряя blocksize
   исходника (у реальных баз бывает 2 и 16).
8. **`PX_write_primary_index`** пишет плоский список записей, а настоящий
   формат `.PX`/`.Ynn`/`.YGn` — **B-дерево** (корень → mid-уровни → листья,
   заполнение = ёмкость−1, covered ≤ 32767, счётчик уровней в `0x20`).
9. **Вторичные индексы** pxlib не пересобирает вовсе.

Решение — «графт BDE-идентичности»: перед записью снимается заголовок
исходного BDE-файла, после записи область имени, version-байты, языковой
драйвер и кодовая страница возвращаются на место; индексы строятся заново
в родном формате из фактического физического расположения записей.

## Установка

```bash
pip install pypxlib   # требует установленной библиотеки pxlib (C)
pip install .         # из корня репозитория
```

macOS: `brew install pxlib`; Debian/Ubuntu: `apt install libpx-dev`.

## Быстрый старт

```python
from pxbde import insert_rows, check_table, list_tables

# 1. ВСЕГДА делайте backup полного комплекта файлов таблицы
#    (.DB/.PX/.MB/.VAL/.X*/.Y*) перед записью — это ваша ответственность.

# 2. Безопасная вставка: pack при дырах → insert без attach .PX →
#    rebuild primary → rebuild всех вторичных → восстановление заголовка
n = insert_rows(
    "DATA.DB",
    [(101, "Иванов", None), (102, "Петров", None)],
    encoding="cp866",
)

# 3. Проверка целостности комплекта файлов
report = check_table("DATA.DB")
print(report["status"], report["issues"])
```

### Отдельные операции

```python
from pxbde import (
    pack_paradox_table,        # RAW-упаковка (устранение free-slots)
    rebuild_primary_index,     # пересборка .PX (составной ключ — из заголовка)
    rebuild_secondary_indexes, # пересборка всех .Xnn/.XGn + .Ynn/.YGn
    describe_table,            # схема + число строк
    secondary_index_pairs,     # пары (X, Y) вторичных индексов
)

pack_paradox_table("DATA.DB")          # записи не пересериализуются (raw)
rebuild_primary_index("DATA.DB")       # B-дерево 1..N уровней
rebuild_secondary_indexes("DATA.DB")   # по текущему физическому расположению
```

## Инкрементальное обновление вторичных индексов (v1.1)

У «старых» боевых баз записи X-файлов часто идут в **историческом порядке
BDE**, который не воспроизводится никакой формулой сортировки (наследие лет
инкрементальных вставок). Полная пересборка такие индексы «чинит» в
неправильный порядок — и приложение BDE перестаёт находить записи.

Поэтому `insert_rows` обновляет вторичные индексы **инкрементально**
(`update_secondary_indexes_incremental`): существующие записи X сохраняют
свой порядок; `Blk Num` освежаются по фактической раскладке `.DB` (в т.ч.
после RAW-pack); удалённые строки выбрасываются; новые вставляются
bisect-ом по локальному порядку; `.Y*` пересобирается поверх. Полная
пересборка (`rebuild_secondary_indexes`) — только явный вызов или fallback.

## Контракт безопасной записи

1. **Backup** полного комплекта файлов до записи.
2. `insert_rows` сам выполняет: PACK при free-slots (raw) → вставка **без**
   привязанного `.PX` → пересборка `.PX` → пересборка вторичных →
   восстановление BDE-идентичности заголовка `.DB`.
3. Строки Alpha длиннее поля обрезаются по байтам кодировки
   (иначе pxlib segfault).
4. После работы приложение BDE нужно **перезапустить** (кэш структуры).

## Валидация

Методика: побайтовое сравнение с файлами, созданными настоящим BDE
(эталонная рабочая база учётной системы, ~130 таблиц):

* пересборка `.PX` (2 уровня) и `.Y02` на неизменных данных даёт файлы,
  **байт-в-байт** равные эталонным (кроме runtime-указателей заголовка);
* 3-уровневый `.PX` — те же blocks/levels/nrec, что у эталона;
* RAW-pack + вставка + пересборка проверены на таблицах до 176k строк
  с 5 вторичными индексами.

## Ограничения

* Пересборка вторичных требует существующего X-файла как источника схемы
  (сам индекс «с нуля» по описанию пока не создаётся).
* Сортировка Alpha-ключей — по байтам кодировки (для cp866-баз соответствует
  BDE 'cyrr'; экзотические сортировки не проверялись).
* Файлы с не-ASCII путями pxlib не открывает (ограничение pxlib).
* Шифрованные таблицы не поддерживаются.
